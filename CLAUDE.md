# Cutroom (shown to users as “Splice & Co.”)

Cutroom is the project name; the app itself is branded **Splice & Co.** (`APP_NAME` and the inline SVG `APP_LOGO` in `index.html`, also the tab icon; `APP_NAME` in `api/_gcal.js` names the Google calendar). Settings can override the name and logo per account. Storage keys and the repo keep the `cutroom` name. It is a task tracker for one video editor's work. Their jobs are either agencies (each with several clients) or direct clients. The app is one file, `index.html`, with no build step. Its only outside dependencies are Google Fonts and, on the hosted copy, supabase-js from jsDelivr. A few Vercel functions in `api/` sit next to it; they use plain `fetch` and no npm packages.

## Where it runs

**Vercel + Supabase (the user's chosen home).** Vercel serves `index.html` and `api/`, and Supabase holds data, pictures and sign-in (Google or an emailed link). Anyone can sign up and gets their own empty tracker. The setup steps for the user are in `SETUP.md`, and the database setup is in `supabase/schema.sql`. Vercel env vars: `SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY, GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, CRON_SECRET` (optional `APP_URL`, `STATE_SECRET`).

### Republishing (don't lose the user's data)

- Update the page in place: publish `index.html` with the Artifact tool and pass the URL above as `url`. Publishing without `url` creates a separate, empty artifact.
- Read the artifact first (`action: "read"`). Build on the live version if it differs from the repo.
- Leave `capabilities` out when republishing, so the stored `{db: {}, assets: {}}` carries forward. Never pass `{}`, because that removes the page's access to its saved data.
- Don't reseed or overwrite the database. It holds the user's real work.
- After publishing, commit the same `index.html` here so the repo matches the live page.

### Feedback via comments

The user leaves requests as comments on the artifact and sends them to Claude. Ask to watch the artifact (ArtifactComments `watch`) at the start of a session. For each request: make the change, republish, commit, then reply in the thread saying what changed and resolve it.

## Data model

There are three storage modes, chosen at startup in `boot()`, in this order:

- **Published artifact:** the `db` capability, with one collection per type. Pictures are uploaded through the `assets` capability, and the asset id is stored and displayed from `/_blob/<id>`.
- **Hosted (`cloudBoot()`):** when `/api/config` returns Supabase settings. The page shows a sign-in screen (`showAuth`) until there's a session. Each document is a row in `docs(user_id, col, id, data jsonb)`, and every write upserts the whole document (`cloudPut / cloudDel`). Changes from other devices come in through `cloudRefresh()`, which reloads every 60s and when the tab regains focus, and is skipped while writes are still on the way. Pictures are stored as `sb:<uid>/<file>` in the public `pictures` bucket.
- **Opened as a local file:** localStorage (`cutroom.data.v1`), seeded from `buildSample()`. Pictures are stored as data URLs.

Collections (document fields):

- `jobs`: `name, type ('agency'|'direct'), color, logo, emoji (optional, shown beside the color dot), order, tools{comms,tracker,upload,storage}, toolLinks{same keys}, folder (Mac path to the job's project files), account (work email), chromeProfile (Chrome profile folder name, e.g. 'Profile 2'), work{days[0-6], hours, shiftStart, shiftEnd (HH:MM, the user's time), pay{amount, currency, period, payday, method}, location, tz (IANA), contact{name, reach}, since, until (contract end), notes}`
- `clients`: `jobId, name, logo, order, brand, hidden, templates, fileName` (jobs also take `templates, fileName`; an old `scratch` field is unused: the scratchpad was removed at the user's request) (only agency jobs have clients)
- `brand` (on a client, or on a direct-client job): `colors[{hex,name}], fonts{head,body}, captions, logo, endcard, cta, music, loudness, dos, donts (one per line), tone, links{guide,assets,refs}, pdfs[{v,name,size,added}], updated, log[{date,text}]`
- `tasks`: `jobId, clientId, clickupId (legacy, from a removed ClickUp import), name, status, priority, start, due (YYYY-MM-DD), format, length, revision, links{task,upload,file,project}, thumb (legacy: no longer shown or set; still deleted with the task), notes, checklist[{id,text,done}], created, updated, doneAt, archived, archivedAt, restoredAt (last restore from Archived; auto-archive counts from it), imported (CSV file name, set by the importer)`
- `settings/log-YYYY-MM` (activity log, one doc per month): `month, items[{at (ISO), kind, text, taskId, task (name at the time), jobId}]`, newest first, at most 2000 per month. Kept in `settings` because the hosted `docs` table only allows jobs/clients/tasks/settings.
- `settings/app`: `statuses [{id,label,color}] (the user's own list and order; empty means the defaults), name, logo, theme ('system'|'light'|'dark'), scheme (a `SCHEMES` id, default 'splice'), textSize (0.9|1|1.12|1.25), density ('comfortable'|'compact'), dayLimit, holidays (country codes; unset means guessed from time zones), backupAt (YYYY-MM-DD of the last backup download), stats (Overview/job page tile keys, see below), and the look/date preferences in `PREF_DEF`: dateRel (bool), dateFmt ('md'|'dm'), weekStart ('mon'|'sun'), hideWeekends (bool), confetti (bool, default true), motion ('system'|'reduce'), contrast ('normal'|'high'), trashDays (7|30|90), darkShade ('standard'|'dim'|'black'), pillStyle ('tint'|'solid'|'outline'|'dot'), tips (bool, hover labels), iconWeight, depth, sideStyle, thinScroll, toastPos, nameWrap, doneStyle, overdueTint, statusIcons, prioColors {urgent,high,low}, logoShape, numFont, readSpacing, sideCounts, compactHeader, greeting, greetName, drawerBand, boardTint, dueStyle, jobProgress, calGrid, todayMark`, plus the focus timer's `pomoFocus, pomoShort, pomoLong (minutes), pomoEvery (sessions before a long break), pomoAutoBreak, pomoAutoFocus, pomoSound ('chime'|'bell'|'soft'|'off'), pomoPopup`, and `allClear, seasonal, officeCat, catSky, catPlant, catVisitors` (bools, default on), `autoArchive` (0 = off, or 3|7|14 days), `catName, catFur` (orange|black|white|grey|calico|tuxedo), `meShow, meHair, meHairCol, meSkin, meTop`, `deskMug, deskLamp, deskCam, deskVinyl`, `stickerShow`, `stickers {id: 'YYYY-MM-DD'}` and `clearRun {d, n}` (sticker book), `plantGoal` (default 20) and `photos` ([ref], up to 4, saved right away) (see Appearance extras and Focus timer)
- `settings/timer` (the focus timer, one per account, synced): `mode ('focus'|'short'|'long'), run ('idle'|'running'|'paused'), endAt (ms), left (ms while paused), taskId, cycle, day, today, dev`. Tasks get `pomos` (finished focus sessions) and `upNext`.

Allowed values:

- Statuses are editable in Settings → Statuses (`statusSettingsHtml`, state on `SM`): rename, recolor, reorder, add and delete. `loadStatuses()` (called in `render()`) rebuilds `STATUSES`/`ST` from `settings/app.statuses`, falling back to `DEFAULT_STATUSES`: `waiting_client, not_started, in_progress, internal_review, revisions, client_review, done`. `done` always exists and can't be deleted. Deleting a status that has tasks asks where to move them; the move happens on Save. Use `stOf(t)` (a task in an unknown status counts as the first one), `stLabel(id)`, `stColor(id)` and `pillStyle(id)` rather than reading `ST`/`STATUS_VAR` directly. The special behaviors below stay tied to the built-in ids and just stop if the user deletes those statuses. The board keeps every status in one row. `isClosed()` marks closed tasks (done, plus the removed `dropped`, which `migrateStatuses()` moves to done on load): they don't count as open, overdue or busy, get no notifications and no calendar events, and can be archived. Moving a task into `revisions` adds 1 to `revision`, moving it to `in_progress` with no start date sets `start` to today (logged; Undo clears it again), and moving it to `done` sets `doneAt`.
- Priorities: `urgent, high, normal, low`.
- `example: true` marks the sample data. The "Clear examples" banner deletes those records.

UI preferences (tab, view, per-tab view `views`, collapsed groups, sort, hidden list columns `hideCols`, task panel width `drawerW`, sidebar width `sideW`) are kept in localStorage (`cutroom.ui.v1`) and never synced.

## Google Calendar (hosted only)

- Each open, non-archived task with a `due` date becomes one all-day event in a "Cutroom" calendar created by the app (scope `calendar.app.created`). The title is `Job · Client · Task`, and the event color follows the job's color (`colorIdFor()` maps the job swatches to distinct Google event colors, other hex values to the nearest one). The event carries `extendedProperties.private.cutroomId`.
- `api/_gcal.js` → `syncUser()` reconciles the calendar with the tasks: it creates, updates and deletes events, and recreates the calendar if the user deleted it. The page calls `POST /api/calendar?action=sync` 4s after any job, client or task write (`calSoon`). `/api/cron` runs it daily for everyone.
- The refresh tokens live in `gcal_links`, which has RLS on and no policies, so only the service role can read it.
- Other routes: `api/holidays.js` (public holidays, see below), `api/backups.js` (restore points, see below), `api/calendar.js` (`status | connect | sync | disconnect`, which needs the Supabase bearer token), `api/calendar-callback.js` (Google redirect, with signed `state`) and `api/config.js`.
- The Settings modal shows Google Calendar and Account (sign out) sections from `accountSettingsHtml()`. They act right away, not on Save.

## Code map (`index.html`)

- **CSS:** color tokens on `:root` for light, redefined for dark under both `prefers-color-scheme` and `[data-theme="dark"]`. Always style through the tokens. Status colors use `--st-*`.
- **Look (Settings → Appearance and Accessibility, `applyLook()`):** color schemes (`SCHEMES`, Slack-style at the user's request) each have a light and a dark accent plus a colored sidebar; `schemeCss()` builds their CSS at startup and they're applied as `data-scheme` on `<html>` (the sidebar restyles its own tokens under `:root[data-scheme] .side`). Text size is the `--ts` multiplier: every px font size in the stylesheet is written `calc(Npx*var(--ts))`, so write new font sizes the same way. Compact density is `data-density="compact"`, with its rules at the very end of the stylesheet. All preview live and are saved with the account.
- **Dates and week (`pref(k)`, `PREF_DEF`, Settings → Appearance):** read preferences with `pref()` (it previews from `SM` while Settings is open). `fmtDate()` honors the day-first format (`absDate`); `fmtRel(s, late)` is for list rows and board cards only ("in 3 days", "2 days late", "3 days ago" within 60 days; `relTitle` puts the plain date in the hover label). The Calendar's month and week grids start on `WS()` (`weekStartOf()`); narrow weekends use `weekCols()` (`--wd/--wk` column widths, `.wk-min` cells show events as thin bars). The CSV importer reads dates day-first when the format is 'dm'.
- **Dark shade and status style (Settings → Appearance, set in `applyLook()`):** `data-dark="dim|black"` swaps the dark surface tokens (rules sit right after the dark token blocks, before high contrast, and only apply while dark). `data-pill="solid|outline|dot"` restyles every `.pill`; the Settings previews are `.pill.pill-demo[data-ps]`, which the root rules skip.
- **Appearance extras (`applyLook()` sets one `data-*` attribute on `<html>` per option; CSS at the end of the stylesheet):** `data-icons` (light/bold stroke), `data-depth` (flat/raised shadows), `data-side` (plain/frosted sidebar), `data-scroll="thin"`, `data-toast` (right/top), `data-names="wrap"` (full task names wrap in list rows, archived rows, pinned cards and phone board cards; board cards always break long words instead of cutting them), `data-done` (plain/faded; default crosses out done list rows), `data-overdue="tint"` (rows/cards get `.is-over`), `data-sticons` (status pill dot becomes a masked icon per built-in status via `pillStyle()`'s `data-st`), `data-logos="circle"`, `data-nums="regular"` (swaps `--mono` for the body font), `data-read="relaxed"` (Accessibility), `data-sidecounts="off"`, `data-head="compact"` (smaller page header), `data-dband="off"` (hides the job-color band on `.d-top`, which gets `--jc`), `data-btint="on"` (board columns tinted from `--sc`), `data-due="badge"` (colored due-date badges in rows, cards and pinned cards), `data-calgrid="subtle|none"`, `data-today="outline|column"`; the Overview greeting (`greetHtml()`, name from `greetName` or the Google account's `B.name`) and job card progress (`jobProgress`: bar, conic-gradient `.jring`, or numbers only, in `jobCard`) are rendered in JS; priority colors are `--pr-urgent/high/low` on `<html>`. Settings rows use `prefRow(k,label,opts,hint)` (compact segmented switch) grouped under Surfaces / Pages / Tasks / Details / Dates; priority colors use `prioColorsHtml()` (`s-prio-col`).
- **Hover labels switch:** `showTip()` does nothing when `pref('tips')` is false (Settings → Accessibility).
- **Sidebar width:** drag `#side-resize` (fixed, desktop only, hidden in the icon rail) between 200 and 400px; saved per device as `S.ui.sideW`, applied as `--sidew` by `applySideW()`; double-click resets to 252px.
- **Accessibility extras:** `data-motion="reduce"` (turns off transitions and animations; use `reducedMotion()` in code) and `data-contrast="high"` (stronger text and border tokens, light and dark), both set in `applyLook()`.
- **Celebration (`celebrate()`):** confetti from the last click point when a task moves to Done (`setStatus` unless `quiet`; the bulk bar calls it once). Off with the setting or reduced motion.
- **Task panel width:** drag `#d-resize` (a sibling right after `#drawer`, desktop only) to resize; saved as `S.ui.drawerW` and applied as `--dw` by `applyDrawerW()`; double-click resets to 760px.
- **Sync status (hosted):** the sidebar footer shows "Last synced …" and, when ClickUp is linked, a "ClickUp checked … ago" line that runs Check now (`cu-sync`; `cuSync` re-renders at start and end); (`noteSynced / syncedAgo`, set on each successful load or write, kept in `cutroom.synced.<uid>`). Tasks changed on another device (found by comparing `updated` stamps before and after `cloudRefresh()`, and against the previous snapshot at startup, `markFresh`) get an accent dot (`freshDot`) until opened (`seenTask`); kept in `cutroom.fresh.<uid>`.
- **Backup reminder (`backupDue`):** a notification when the last backup download (`settings/app.backupAt`) is 30+ days old, or 30 days after the first real task if there's never been one. Clicking it opens Settings → Backup, which also shows the last backup date.
- **Notes formatting (`notesBlock / mdLite / mdInline / notesFormat`, state `NOTES_EDIT`):** task notes stay plain text with light markdown (`**bold**`, `*italic*`, `- ` bullets, `1. ` lists, `# ` headings, `[text](url)` and bare links, opened through `linkHref(url, job)`). The panel shows them formatted; clicking (or Edit) switches to the textarea with a toolbar (B, I, bullets, numbers, link; ⌘B/⌘I inside the textarea; Enter continues a list, Enter on an empty item ends it). Leaving the textarea shows the formatted view again. Empty notes and drafts are always in edit mode. Escape everything through `esc` first (mdInline does).
- **Checklist reorder:** drag a step's grip (`.ck-grip`, pointer events, `CKD / ckDrop`) above or below another step; saves the new `checklist` order.
- **On shift (`onShift(job) / shiftDot`):** a green dot after a job's name in the sidebar while the current time is inside its shift (`work.days` + `shiftStart/shiftEnd`, the user's own time; overnight shifts count from the start day). Updated by the 60s re-render.
- **Sidebar position:** `.side` is `position:sticky` (desktop) / `fixed` (phone); don't give it another `position` rule, or it scrolls away on long pages.
- **Address bar (`urlOf / parseUrl / applyUrl / syncUrl`):** the page's place lives in the hash: `#/overview`, `#/archived`, `#/job/<id>/client/<id>/pane/<details|brand>`, plus `/task/<id>` while a task is open. `syncUrl()` (end of `render()`, `openTask`, `closeDrawer`) pushes a history entry for page changes and for opening a task, replaces it when switching tasks, and closing a panel it opened goes `history.back()`, so the browser's Back closes the panel or returns to the previous page (`popstate` → `applyUrl`). `#/task/<id>` alone opens that task on its job (Copy link button in the panel's top bar, `copyTaskLink`). Hashes that don't start with `#/` (Supabase sign-in) are left alone until the app is ready.
- **Per-page view:** each job (and the Overview) remembers List / Board / Calendar in `S.ui.views[tab]`, restored in the `nav` handler.
- **List options (`#vopt`, `renderVopt`, `rowsAttrs()`):** the sliders button in the toolbar (List view only) hides Priority, Start and Links columns (`S.ui.hideCols`; rows get their grid from `--cols` / `--cols-mid` set on `.rows`, and `--w0` for the first column), and expands or collapses every status group.
- **Search inside tasks:** the `#q` filter also matches checklist steps and links (and notes, as before). Matches are highlighted (`hlText`, `<mark>`), and when the hit isn't in the name, a line under the row or card shows where (`searchHit`: Notes / Checklist / the link's name).
- **More sorts and the Missing filter:** Sort adds Recently updated, Oldest assigned (`assignedOn`), Most revisions and Client. The due-date filter has a "Missing" group (`miss-any | miss-upload | miss-file | miss-task`, `missing()`), open tasks only.
- **Descript as file storage:** one job sends its shoots as Descript links, so `Descript` is a File storage choice (`TOOL_ROLES`); with it, the task's `links.file` is labeled "Descript files" (`linkLabel`).
- **Links in the task panel:** only filled links show; empty ones are "+ <link name>" buttons (`link-add`, remembered in `LSHOW` while the panel is open). Known services get their own icon (`SVC`, `svcIcon(url)`: Frame.io, Google Drive, OneDrive, ClickUp, LucidLink, Descript, Dropbox, Vimeo, YouTube) in list rows, board cards and the panel.
- **Sample data:** `/*SAMPLE-START*/ … /*SAMPLE-END*/` holds the date helpers plus `buildSample()`.
- **Persistence:** `create / patch / remove / flush`. Writes are optimistic and queued per document. Text fields are debounced with `patch(col, id, p, 600)`.
- **Sidebar (`renderSide`):** the app logo and name (sidebar and phone top bar) are buttons that go to Overview. Then Overview, then a **Jobs** item that folds the job list open or closed (`S.ui.jobsOpen`, remembered), then Archived, Activity and Trash below the job list (user's order). Jobs can be dragged to reorder (`jobDrag`, sets `order`). The ‹ button collapses the sidebar to an icon rail on desktop (`S.ui.sideMini`, `body.side-mini`). Clients aren't listed in the sidebar; they're tabs on the job page. Task search (`#q`) sits top-right of the page header (`#top-search`). The toolbar holds the List / Board / Calendar switch (`.seg`, back in the toolbar at the user's request; don't move it to the sidebar), the priority, due-date and sort filters, and New task. Settings sits in the footer on its own line under the save status. Edit buttons use `I.pencil`; `I.gear` is the Settings cog.
- **Breadcrumbs (job pages):** `Overview › Job › Client › Details/Brand guide` above the job name. The first crumb is where the user came from (`S.ui.from`, Overview or Archived, set in the `nav` handler). Crumbs use `data-act="nav"`, which also takes `data-pane`.
- **Activity log (`logAct(kind, text, {task, jobId})`, `logItems()`, `renderActivity()`):** the sidebar's **Activity** page (tab `activity`, after Archived) lists changes by day with search, a job filter and a kind filter; the task panel has **Details / Activity** tabs (`S.ui.dtab`, reset to Details when another task opens; entries on the Activity page open straight to it via `data-dtab`). The Activity tab (`activityPane / taskActivity`) is the task's timeline, newest first, with a composer to post your own updates (kind `note`, ⌘/Ctrl+Enter; deletable with a double click, `deleteNote`). Tasks made before the log existed get a synthetic Created entry from `created`. Logged: task created, status moves (with revision round), due/start dates, priority, job/client moves, checklist steps checked off, archive/restore, deletes, job added/edited/deleted, clients added/removed, brand guide saves. Name, notes and link typing isn't logged (too noisy). Drafts never log. `pruneLog()` (run from `migrateStatuses()`) deletes months older than 12. Add a `logAct` call when you add a new kind of change.
- **Updates: resolve and reply (`noteHtml / updateNote / toggleNoteDone / postReply / deleteReply`, Frame.io style):** each posted update (log kind `note`) has a round ✓ that marks it done (`done, doneAt` on the log item: text crossed out, "Done <date>") and a Reply button that opens an inline box (`REPLY_AT`, ⌘/Ctrl+Enter posts, Esc cancels) adding `replies:[{at,text}]` (delete with a double click, `replyDelArmed`). A timecode at the start of a line (`12:25`, `00:14:35;07`, `TC_RE`) shows as a yellow chip. The Activity tab shows "N open · N resolved" with Hide resolved (`S.ui.hideResolved`); list rows and board cards get a chat chip with the count of open updates (`openNotes`, cached per render in `NOTE_OPEN`). Resolving and replying aren't logged as separate entries.
- **Updates: formatting, pictures, edit (`fmtBar / noteText / attAdd / attHtml / picsHtml / openLightbox / saveEdit`):** the update box and the reply box have the same formatting toolbar as Notes (`fmtBar(textareaId)`, `notesFormat(f, textarea)`; ⌘B/⌘I and list continuation work there too), and updates render through `mdLite` with timecode chips. Pictures: the Picture button (`#upd-pics-in`), pasting a screenshot, or dropping images on the box (`[data-drop-pics]`) uploads them right away with `storeImage(file,1920,1280,'image/jpeg')` into `ATT.note / ATT.reply`; posting saves them as `pics:[ref]` on the update or reply (`logAct(..., {extra})`). Unposted ones are dropped on cancel or task change; deleting an update or reply drops its pictures. Thumbnails open a lightbox (`#lightbox`, `LB`, arrows / Esc / click outside, "Open full size"). The pencil on an update edits its text in place (`EDIT_AT`, sets `edited`).
- **Workload:** `dueLoad()` counts open tasks due per day across all jobs; a day is busy at `dayLimit()` or more (`settings/app.dayLimit`, default 3, set in Settings). Busy days are flagged on the Calendar (`.busy-tag`), in the task panel under Dates, and in notifications.
- **Notifications (`notifications / renderBell / openNote`):** the bell top-right, next to search (`#bell`, panel `#notes`). The list is rebuilt from the tasks on every render: overdue, due today, due tomorrow (with checklist steps left), busy days in the next 7, starting today but not started, stuck in Internal review or Revisions for 3 or more days (by `updated`), revision round 3 or more, and urgent or high priority with no due date. Clicking one opens its task (a busy day opens the Calendar). Read and dismissed keys are kept per device in localStorage (`cutroom.notes.v1`). Keys include the date they refer to, so a moved deadline notifies again. The user removed the earlier Today page; don't bring it back.
- **Work details (`workOf / workForm / workCard`):** per-job schedule, pay, location and contact, edited in the job modal ("Work details", inputs use `data-mw="path"`) and shown in the job page's **Details** tab (`detailsPane`), next to Tasks and Brand guide. The Details tab also holds the job's tool boxes (`toolsHtml`), which are no longer in the header. Each tool box has a colored icon tile (`toolTile`: the role's icon, on the tool's brand color from `TOOL_COLORS` when it's a known tool). The work-details card (`workCard`) puts its items in `.work-grid` (auto-fit, so they share the full width) and the notes below it, outside the grid; a notes cell spanning the grid kept empty columns open. The job header is just the name with a pencil (Edit job) and the type. The Tasks / Details / Brand guide tabs and client tabs render into `#subnav`, a full-width row below the header. Overview job cards are compact on every screen size (user's request): only the name, the status bar, open/overdue/revisions counts and the next due task. The type/tools line (`.jm-type`), the schedule line (`.when`) and the Overview subtitle's tail (`.sub-tail`) are hidden with CSS. The Overview header totals scheduled hours per week. Time differences come from `Intl` (`tzOffset`, `tzDiff`) against this device's time zone (`MY_TZ`). A 60-second tick redraws only the sidebar and notifications; the whole page every 5 minutes or when the day changes (`TICK`), so "time there" can lag up to 5 minutes. `cloudRefresh` skips the redraw when nothing changed (`dataSig()`). The user is paid a fixed monthly amount; invoices live in the job's Invoices tab (added at the user's request), but there's still no time tracking.
- **Brand guides (`brandOf / brandPanel / brandForTask / openBrand / saveBrand`, state in `BM`):** agency clients each have one, and direct-client jobs have one on the job. A task uses its client's guide, or its job's when it has no client (`brandHome`). It lives in the job page's own **Brand guide** tab (`S.ui.pane`, set by the Tasks / Brand guide tabs under the job header; `brandPane()` shows the direct client's guide, the selected client's, or one card per client on "All clients"). The user found it too busy above the task list, so keep it out of the Tasks tab. It also shows and as a collapsible section in the task panel, with "Add do's & don'ts to checklist" (`brandToChecklist`, which skips duplicates). Saving adds a change-log entry (the user's note, or a list of what changed). PDFs upload through `storeFile()`: artifact assets, Supabase `pictures` bucket (PDFs allowed since schema update), or a data URL up to 2.5 MB locally.
- **Rendering:** `render()` calls `renderSide()` and `renderMain()`. `renderMain` branches to overview, job tab, or `renderArchive()`. The views are `listView / boardView / calendarView`. The task panel is `renderDrawer()` (760px wide on desktop). Its fields follow ClickUp's layout at the user's request (`.props2`): two columns of label + value (one column when the panel is under 600px, via a container query on `.d-body`), borderless controls that show a background on hover, a status pill tinted like the board and list pills (see-through color, colored dot and text) with a next-status › button (`d-next`) and a ✓ mark-done button (`d-done`), Start → Due on one full-width row, and a priority flag colored by priority.

Settings, the job modal and the brand guide editor use the Slack-style layout the user asked for (`prefLayout(key, active, sections)`: section list on the left, one section on the right; a sideways tab row on phones). - **Bulk move (`moveTasks(ids,'j:<job>'|'c:<client>')`):** the bulk bar's **Move to…** select moves ticked tasks to another job (no client) or a client, logged, with Undo.
- **Task age (`assignedOn`, `ageDays`, `ageNote`):** assigned = start date, else created. Open tasks assigned 7+ days ago show a `12d` chip in their meta line (amber from 14 days); the task panel shows "Assigned 12 days ago" under the dates (or "Finished N days after it was assigned").
- **Public holidays (`holidayMap / loadHolidays / holHtml`, Settings → Holidays):** shown on the Calendar's month and week views (`.hol`, day tinted `.holiday`). Countries are `settings/app.holidays`; until the user edits the list it follows this device's time zone plus each job's `work.tz` (`tzCountry`, `TZ_CC`). Hosted mode fetches `/api/holidays?c=CC&y=YYYY` (Google's public holiday .ics feed, skipping observances; Nager.Date fallback), other modes Nager.Date directly. Cached in localStorage `cutroom.hol.v1` for 30 days. Display only: holidays don't change busy days or notifications.
- **CSV import (`parseCSV / impColumns / importPlan / runImport`, Settings → Import CSV):** reads a tracker sheet downloaded as CSV (the user's Google Sheet: Client, Reel Title, No of Drafts, Date Assigned, Deadline, Status, Notes, OneDrive, ClickUp, Frame) or the app's own export. Finds the header row, maps columns by name (`IMP_COLS`), skips title/month rows, maps statuses by label then keywords (`impStatus`), dates as MM/DD/YYYY, matches clients by name (creating new ones on agency jobs), and skips tasks that already exist (same job, client and name). Shows a preview first; a Job column routes rows to jobs by name. Import closes Settings without saving other changes (like Restore).
- **Multi-select (`SEL`, `selBox`, `renderBulk`):** turn on **Select** in the toolbar to show checkboxes on tasks (`selBox` renders nothing otherwise; the user found hover checkboxes distracting) and tick them; Shift-click selects a range. The floating `#bulk` bar sets status, priority or due date, archives, or deletes (click twice) for all ticked tasks, each change logged. Esc clears.
- **Rename in place (`startRename`, `nameClickT`):** double-click a task name in the list or board to edit it (Enter / click away saves, Esc cancels). A single click on a name waits 230ms before opening the task so a double-click can cancel it.
- **Manual order (`order`, `dropOrder`, Sort "My order"):** list rows and board cards are draggable; dropping onto another task inserts it before/after (blue line), renumbers that status group's `order` (1000, 2000…) and switches Sort to `manual`; dropping into another group/column also changes status. Groups are `section.group[data-drop]`.
- **Pins were folded into Up next (user's pick):** `migrateStatuses()` moves any `pinned` task to the top of Up next once and clears `pinned`; there's no pin button or menu item. `pinnedStrip(scope)` now shows the first 3 Up next tasks in scope ("Up next", `#n`, × = remove from the queue via `unpin` → `toggleUpNext`, See all → the Up next page) on the Overview and job pages.
- **Week view (`weekView`, `S.ui.calMode`, `S.ui.week`):** Calendar has a Month / Week switch; Week shows 7 day columns with every task due that day (stacked day cards on phones: the phone CSS overrides the inline `grid-template-columns` from `weekCols()` with `!important`, which is what broke it before). Each day's header shows the work hours scheduled that day (`.wd-hrs`: each working job's `work.hours`, or its shift length when hours are empty; hover lists them per job). Under each day's holidays, `.wshift` bands show the shift hours of the current job (or every job on the Overview) on its work days.
- **No monthly summary:** the user tried a Monthly summary page and asked to remove it; don't add it back.
- **Trash (`deleteTasks / restoreTrash / purgeTasks / purgeOldTrash`, tab `trash`):** deleting a task sets `deleted:true, deletedAt` instead of removing it; `live()`, `archived()`, quick search and the calendar sync skip deleted tasks. The Trash page restores, deletes for good (click twice) or empties; tasks older than 30 days (`TRASH_DAYS`) are removed on load. Deleting a whole job or clearing examples still removes for good.
- **Job color stripe:** list rows and board cards have a 3px left border in their job's color (`--jc`).
- **CSV export (`exportCSV(jobId|'all')`):** the download icon next to the job name, or Settings → Backup. Layout copies the user's own tracker sheet (no Notes): a title row, headers (Client, Reel Title, No of Drafts = revision round, Date Assigned = start or created, Deadline, Status, then the job's storage / tracker / review tool names with the task's links), and a month row (by date assigned) above each month's tasks. Includes archived tasks, not Trash. UTF-8 with BOM for Excel.
- **Offline (`sw.js`, `OUT`, `cloudWrite / flushOut / saveSnap`):** `sw.js` caches the page (network-first), icons and supabase-js so the app opens without internet. In hosted mode the data is snapshotted to localStorage (`cutroom.snap.<uid>`, also `cutroom.cfg` and `cutroom.lastuid`), and writes that can't reach Supabase wait in an outbox (`cutroom.outbox.<uid>`), sent on the `online` event and every 30s. The sidebar footer shows "Offline · N changes waiting to sync". Calendar sync and `cloudRefresh` pause while offline or while the outbox has items.
- **Board:** one column per status in a single row (`grid-auto-flow:column`), scrolling sideways. On desktop widths columns are at least 236px (they used to squeeze to 160px and break names mid-word in a narrow window); list and card names get `<wbr>` after underscores so file-style names (`260927_Lema_V2`) break at the underscores.
- **Pull to refresh (`PTR / ptrShow / ptrGo`, `WPT`):** at the top of the page, a touch pull down (not starting in the sidebar, panel, dialogs, tab bar or a board card) or a trackpad/wheel scroll up that starts after resting at the top for 450ms (so momentum doesn't count) shows a pill (Pull / Release to refresh) and reloads the page. `html{overscroll-behavior-y:contain}` turns off the browser's own pull-to-refresh so there's one behavior everywhere. Long status names are cut short with … in the column and group headers (`.pill .pl`), so the task count always stays inside.
- **New tasks are drafts (`DRAFT`, `newTask / saveDraft / discardDraft`):** New task (toolbar button or the `n` key) opens the panel with an unsaved draft kept only in `S.tasks` on this page. `patch` and `remove` on it never write, `live()` skips it, and reloads keep it. **Save task** (needs a name) creates it for real; Cancel, Escape, closing the panel or opening another task discards it. There are no other add-task shortcuts (no per-group quick add, board "Add task" or calendar day +), at the user's request, to avoid accidental tasks.
- **Events:** delegated `click / change / input / submit` handlers switch on `data-act`. Give re-rendered inputs a `data-fk` so `withFocus()` keeps focus while typing.

## Conventions

- Git: the user wants every change shipped without asking. Commit to the working branch, push, open a pull request into `main` and merge it yourself (GitHub MCP tools), so Vercel deploys it. Don't republish the artifact (the user no longer wants it updated).

- Keep the app a single HTML file, and keep the artifact viewer's frame limits in mind. `alert()`, `confirm()` and `prompt()` don't work, so build confirmations in the page (click twice to delete). Use `el.hidden`, not `style.display`.
- The layout must work at phone width (about 400px, breakpoint at 820px).
- Write interface text in plain, specific wording ("Archive", "Restore", "Delete for good").

## Testing

Open the file locally with Playwright to check a change. Chromium is at `/opt/pw-browsers/chromium`, so use `executablePath` and don't run `playwright install`. Opened as a local file, the page runs in localStorage mode with the sample data. Screens redraw on the next animation frame, so wait about 150ms before checking the page. Syntax-check the script with `node --check` after pulling it out of the `<script>` tag. To test the hosted mode without real services, serve the page from a small local server that answers `/api/config`, and use Playwright `route()` to swap the jsDelivr supabase-js URL for a fake `window.supabase.createClient`. Test `api/` by stubbing `global.fetch` in Node.
